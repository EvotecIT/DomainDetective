One engine, four surfaces

Check it once.
Automate it forever.

The browser tools run the same DomainDetective library you install. When a one-off check becomes a weekly report, a CI gate or a fleet audit, the code is already written for you.

  • {{ icon_name = "browser"; include "icon" }}Browser DNS checks run locally through DNS-over-HTTPS. Nothing to install.
  • {{ icon_name = "terminal"; include "icon" }}PowerShell 150+ Test-DD* cmdlets that pipe into Word, HTML and Markdown reports.
  • {{ icon_name = "code"; include "icon" }}.NET DomainHealthCheck for services, scanners and dashboards.
  • {{ icon_name = "bolt"; include "icon" }}CLI JSON output for pipelines, cron jobs and incident runbooks.
weekly-mail-report.ps1
Install-Module DomainDetective -Scope CurrentUser

# One domain, every check
Test-DDDomainOverallHealth -DomainName 'contoso.com'

# Mail posture for many domains, straight into a Word report
Export-DDSecurityReport -ExportFormat Word -ExportPath '.\Reports' {
    Test-DDEmailSpfRecord   -DomainName contoso.com, fabrikam.com
    Test-DDEmailDkimRecord  -DomainName contoso.com, fabrikam.com
    Test-DDEmailDmarcRecord -DomainName contoso.com, fabrikam.com
}
Program.cs
using DomainDetective;

var health = new DomainHealthCheck();
await health.Verify("contoso.com");

Console.WriteLine(health.SpfAnalysis.SpfRecord);
Console.WriteLine(health.DmarcAnalysis.Policy);

// Everything DomainDetective found, ready to store or ship
File.WriteAllText("contoso.json", health.ToJson());
terminal
# Mail authentication only, summarised
domaindetective check contoso.com --checks SPF,DKIM,DMARC --summary

# Full scan as JSON for a pipeline gate
domaindetective check contoso.com --json > contoso.json
